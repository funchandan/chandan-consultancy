Field reps coordinate parts at the hospital—orders, serials, delivery, surgical use, and returns—without phone calls and spreadsheets splitting the story.

Problem Status lives in fragments

Reps, surgeons, and hospital ops each hold partial context. Orders, parts, deliveries, usage, and returns sit in different tools—so the next action is ambiguous under time pressure.

Solution One thumb path through the visit

A rep-primary mobile flow from arrive through close loop, with a wireframe visible at every gallery beat.

Arrive

Active hospital, surgeon, and case on one screen.

Jordan opens the visit knowing where they are and who they are supporting.

Rep identity, hospital, surgeon, and case ID sit above the fold so every later action inherits the same context.

Design lens

Visibility of system status

Reps could not tell which visit was active when status lived in email threads and spreadsheets.

Arrive screen: hospital, surgeon Dr. Vasquez, and case PO-48291 as the anchor for the visit.

Preferences

Surgeon kits and sizes before the cart opens.

Stored preferences surface at the start of the visit—not after a wrong line is placed.

Kits, brands, and history are grouped for confirm-or-edit before order build.

Design lens

Recognition rather than recall

Surgeons should not have to repeat kit choices every visit; reps should not guess from memory.

Preferences list with last-used kit, sizes, and edit affordance tied to the surgeon record.

Order

Line items tied to the visit, not a desk PO.

The cart is built beside the surgeon with clear ownership and submit state.

Quantities, surgeon association, and approval-needed states stay in the visit—not a back-office form.

Design lens

Match between system and real world

Ordering looked like procurement software; reps think in cases, surgeons, and trays.

Order screen with line items, surgeon chip, and primary submit in visit context.

Order track

Order state without calling ops.

Placed → confirmed → fulfilled reads as a timeline with owner and ETA.

Exception states are visible on the same screen so reps do not chase status by phone.

Design lens

Visibility of system status

I need to know if this serial is in the building—not just that the order shipped.

Order timeline with confirmed step active, ETA, and exception affordance.

Part track

Serial-level status, not just the PO rollup.

Each line shows lot/serial and a status distinct from order-level progress.

Reps can answer surgeon questions about a specific part without opening another system.

Design lens

Visibility of system status

Order shipped is not the same as part received at the hospital—or consumed in the OR.

Part list with serial SN-8842, linked order, and in-transit vs on-site states.

Deliver

Shipment and part-at-site in one beat.

Delivery splits carrier shipment from part received at hospital or OR shelf.

Both segments use the same visual language so handoff to surgical use is obvious.

Design lens

Consistency and standards

Split delivery states were described differently in ops tools and rep notebooks.

Deliver view with shipment in transit and part received segments.

Use

What was consumed in surgery, with case ID.

Usage is recorded against the procedure with timestamp and confirmation.

Implanted and consumed lines support audit-friendly lifecycle without a separate form.

Design lens

Error prevention

Wrong consumption records create compliance risk; the UI ties use to the active case.

Surgical use screen with case ID, consumed parts, and confirm action.

Return

Send-back in the same flow as the order.

Returns are flagged with reason, pickup, and ship-back status beside open orders.

Reps do not switch apps when a tray line must go back.

Design lens

Flexibility and efficiency of use

Returns were a phone call and spreadsheet row; they belong in the visit lifecycle.

Return list with reason codes and pickup scheduled state.

Request

New SKU intake when catalog gaps block the case.

Missing catalog lines capture justification and approval workflow in one request.

Context from the visit carries into intake so ops does not re-ask the hospital story.

Design lens

Help users recognize, diagnose, and recover from errors

Catalog gaps used to stall cases; intake now starts from the surgeon and case already on screen.

New part request form with SKU gap, justification, and pending approval state.

Close loop

Open work visible before leaving the hospital.

Visit summary shows open orders, returns due, and preference updates.

Reps leave with nothing ambiguous—next actions are listed, not implied.

Design lens

Visibility of system status

Surgeon prefs should show up before I build the cart again.

Close loop summary with open orders count, returns due, and preference delta.
