Start here

Freya’s golden rules before you open Excalidraw.

Who this is for

RoleWhy run this
UX designer (Freya)Structure-only layouts Mimir can implement without design debates
PM / founderReadable flow artefacts without high-fidelity polish
BuilderOne .excalidraw per screen with labelled regions

What you’ll have

  • No annotations in the wireframe; rationale in step .md spec
  • Canvas: desktop 1440 × 900 or mobile 390 × 844, background #f8f9fa
  • Clean lines: roughness: 0, WDS palette from wireframe skill
  • Buttons grouped with labels via shared groupIds

Why wireframes

Concrete shift in how specs reach build - not “draw more screens” advice.

Before Screenshots or prose-only specs; engineers guess layout.

After One Excalidraw file per page slug under work/design/wireframes/ - WDS installs may use _bmad-output/D-UX-Design/wireframes/ instead. Builders implement from structure without design debates on Slack.

Walkthrough

4 steps · ~20 min · copy-paste paths

Run in order. Steps 1 - 3 set up structure; step 4 is the exit check.

  1. Step 1 Choose slug and path.2 min 
    work/design/wireframes/[page-slug].excalidraw
# WDS installs may use:
# _bmad-output/D-UX-Design/wireframes/[page-slug].excalidraw
# Education samples on this site:
# toolkits/artefacts/wireframe-with-excalidraw/sample-flow.excalidraw
    Expected: file path matches page slug; one screen per file.

    If it fails: Wrong canvas size mixed on one frame - split mobile and desktop into separate files.

  2. Step 2 Set canvas size.3 min

    In Excalidraw, set background #f8f9fa. Frame mobile at 390×844 or desktop at 1440×900.

    Expected: frame dimensions match target breakpoint; background colour set.

    If it fails: Hand-drawn roughness - set roughness: 0 for production wireframes in WDS.

  3. Step 3 Draw regions only.10 min

    Nav, content cards, primary CTA. Use grey bars (#dee2e6) for body text placeholders; real text only when words matter for comprehension.

    Expected: every interactive region visible; no callout annotations on canvas.

    If it fails: Icons without labels - use labelled rectangles for icon slots per Freya rules.

  4. Step 4 Export for HTML embed (optional).5 min

    Export PNG/SVG for toolkit pages; keep .excalidraw as source of truth.

    Exit: developer can open file and see every interactive region without reading a paragraph spec.

    If it fails: PNG looks fine but SVG embed breaks - keep .excalidraw as source; export SVG with Arial-friendly labels only.

Troubleshooting

Symptom → fix, tied to the step where it usually appears.

  • Annotations on canvas. Step 3 - Move callouts to the step markdown; wireframe stays structural.
  • Hand-drawn roughness. Step 2 - Set roughness: 0 for production wireframes in WDS.
  • Wrong canvas size. Step 1 - Mobile and desktop mixed on one frame confuses implementation - one screen per file.
  • Icons without labels. Step 3 - Use labelled rectangles for icon slots per Freya rules.
