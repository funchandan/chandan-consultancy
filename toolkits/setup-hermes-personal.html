Personal Hermes AI stack

Install Hermes from upstream, run the background gateway, schedule cron jobs, and add a .hermes.md project context file - so repo-aware automation runs without babysitting the CLI.

Prerequisites: macOS or Linux, Node 18+, a git repo you want the agent to work in, ~30 minutes.

After this walkthrough Hermes CLI on your PATH, the gateway running via launchd (or systemd on Linux), at least one scheduled cron job, and .hermes.md at repo root describing loops, paths, and stop conditions.

Optional on this site: maintainers who publish education walkthroughs may wire a toolkit-education cron instead - see Toolkit review loop. That is not the default user outcome below.

  • ~30 min
  • Self-serve
  • Hermes CLI + gateway
  • Open-source upstream

Who this is for

RoleWhy run this

BMAD / WDS practitionerPair Hermes cron with BMAD skills and design handoffs in the same repo

What you’ll have running

  • hermes CLI on your PATH (v0.17+)
  • Gateway daemon installed (launchd on macOS) - cron fires without an open terminal
  • One scheduled job (e.g. nightly doc review or PR hygiene check)
  • .hermes.md at repo root with loops, paths, and conventions
  • Optional: hermes-agent/ submodule with upstream skills

Why Hermes

Concrete shift from ad-hoc chat to scheduled, repo-aware automation - not generic agent hype.

Before You re-explain repo context every session and manually re-check stale docs or open PRs.

After Cron runs on a schedule with --workdir set to your repo; .hermes.md loads priority loops and paths - typically saving 1 - 2 hours per review cycle on recurring hygiene tasks.

Walkthrough

6 steps · ~30 min · copy-paste commands

Run in order. Each step lists expected output so you know before moving on.

  1. Step 1 Install Hermes. Follow the upstream installer or use the binary already on your machine.5 min 
    curl -fsSL https://hermes-agent.ai/install.sh | bash
hermes --version
    Expected: version string (e.g. 0.17.0). If command not found, add ~/.local/bin to PATH.

    If it fails: Command not found after install - add ~/.local/bin to PATH and open a new shell.

  2. Step 2 Migrate config and set workdir.5 min 
    hermes config migrate
hermes config set terminal.cwd "/path/to/your/repo"
    Expected: config version bumps (e.g. v0 → v30). terminal.cwd points at the repo Hermes should treat as home.

    If it fails: hermes setup needs a TTY - run the interactive wizard in a real terminal; use hermes config set for non-interactive keys.

  3. Step 3 Enable curator (optional).2 min 
    hermes config set curator.enabled true
    Curator helps Hermes prioritize context files like .hermes.md and skills.

    If it fails: Curator flag not recognized - confirm Hermes v0.17+ with hermes --version before retrying.

  4. Step 4 Install the gateway.5 min 
    hermes gateway install
hermes cron status
    Expected: gateway running (launchd plist on macOS). Cron scheduler reports active.

    If it fails: Cron never runs later - gateway not installed; rerun hermes gateway install and confirm with hermes cron status.

  5. Step 5 Create a cron job.10 min 
    hermes cron create \
  --name doc-hygiene-review \
  --workdir "/path/to/your/repo" \
  --skill requesting-code-review \
  "every 12h" \
  "Read docs/CHANGELOG.md and open PRs. Flag stale sections and missing links. Log findings to progress/review-log.md."
    Expected: job ID returned; hermes cron list shows schedule and workdir. Rename paths and prompt for your team’s hygiene task.

    If it fails: Job runs in wrong directory - set --workdir to an absolute path; relative paths break when launchd starts the gateway.

  6. Step 6 Add .hermes.md.5 min

    Copy the template from downloads. List priority loops, paths, and stop conditions your team agrees on.

    Exit: agent sessions launched from this repo load context without re-pasting instructions.

    If it fails: Skills not found - install Hermes skills into the repo (npx skills add ./hermes-agent/skills) or attach via --skill on cron create.

Troubleshooting

Symptom → fix, tied to the step where it usually appears.

  • Cron never runs. Step 4 - Gateway not installed; run hermes gateway install and confirm with hermes cron status.
  • Job runs in wrong directory. Step 5 - Set --workdir to an absolute path; relative paths break when launchd starts the gateway.
  • hermes setup needs a TTY. Step 2 - Run the interactive wizard in a real terminal; use hermes config set for non-interactive keys.
  • Skills not found. Step 6 - Install Hermes skills into the repo (npx skills add ./hermes-agent/skills) or attach via --skill on cron create.
  • Agent invents tasks outside scope. Step 5 - Tighten the cron prompt with explicit file paths and forbidden actions.
