Start here

Confirm fit and the end state before you install more skills.

Who this is for

RoleWhy run this

Agent practitionerStop skill roulette; start from named defaults
Team leadShareable skills-picks.yaml with install commands

What you’ll have

  • Audit of .agents/skills/ and skills-lock.json
  • Targeted installs via npx skills add --skill
  • skills-picks.yaml with ≤10 example skills documented (replace with your stack)
  • Top skills referenced in .hermes.md or AGENTS.md

Why curate

Concrete shift in how agents pick skills - not “install everything” advice.

Before 70+ Hermes skills installed with --all; agents pick generic skills or hallucinate workflows.

After Ten named skills with *when to use* documented; new sessions start from bmad-help or .hermes.md instead of skill roulette.

Walkthrough

4 steps · ~25 min · copy-paste commands

Run in order. Each step lists expected output so you know before moving on.

  1. Step 1 Audit installed skills.5 min 
    ls .agents/skills/
cat skills-lock.json | head -40
    Expected: list what is pinned and where it came from (source, computedHash).

    If it fails: Empty skills folder - run Set up BMAD or Personal Hermes stack first.

  2. Step 2 Install from a known source.10 min 
    npx skills add ./hermes-agent/skills --skill requesting-code-review -y
npx skills add bmad-code-org/BMAD-METHOD --skill bmad-help -y
    Expected: prefer targeted --skill over --all unless you need the full Hermes bundle.

    If it fails: Duplicate skill names - prefer one source per skill name; see troubleshooting.

  3. Step 3 Hermes skill list (optional).2 min 
    hermes skills list
    Expected: confirms what Hermes CLI sees vs Cursor .agents/skills/.

    If it fails: CLI list differs from Cursor - check both paths; Hermes may use a separate skills directory.

  4. Step 4 Pin in project context.8 min

    Copy skills-picks.yaml to your repo. Reference top skills in .hermes.md or AGENTS.md so cron and chat sessions use the same list.

    Exit: team agrees on ≤10 default skills; rest on demand.

    If it fails: Agent ignores skills - mention skill by name in prompt or attach via Cursor rules / Hermes --skill.

Troubleshooting

Symptom → fix, tied to the step where it usually appears.

  • Skill hash drift. Step 2 - Re-run npx skills add after upstream updates; commit new skills-lock.json.
  • Duplicate skill names. Step 2 - BMAD and Hermes may overlap; prefer one source per skill name.
  • Agent ignores skills. Step 4 - Mention skill by name in prompt or attach via Cursor rules / Hermes --skill.
  • Too many skills. Step 4 - Cap at ~10 defaults; document the rest in a catalogue file like this page.
